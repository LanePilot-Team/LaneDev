# 已知失效的人工設定（2026-08-01 盤點）

`npm run audit:dead-settings` 會直接比對「journal 說要有」與「建置端實際產出」
（`buildTurnBays` / `buildRightLanes` / `buildMotoBoxes` 的 key），列出按了卻不會出現的設定。
這份是當時的盤點結果與處置決定，避免同一批東西被反覆重查。

## 機車停等格：13 筆保留不動

全部同一個原因——**鍵指到的節點已不在活躍路網**。journal 只增不減，這些紀錄留著，
不遷移也不刪除：座標配對遷移在這個專案實測過品質很差（曾把標註搬到不相干的路上），
而刪除會讓「以前確實標過」的事實消失。稽核會持續把它們列為失效，這就是它們的狀態。

| 23875894 / 297138323 | 援中路 / 藍昌路 | `-3871383230009`、`-3871383230010`（couplet 合成負節點） | 4 |
| 24204249 | 軍校路 | `3004962040`、`3004962043` | 2 |

軍校路那 9 筆與 shard 重複／way id 變動是同一片區域；couplet 負節點那 4 筆是合併結果
改變後鍵就對不上。兩者都不是編輯器邏輯能修的，要修得等重跑
`build_static_road_database.mjs`（那時 way id 本來就會變，一併重標）。

## 偏心左轉道：6 筆是設定前提沒滿足（不是 bug）

把前提補齊，既有的 `present:1` 就會直接生效，不必重按。

- **中央帶寬 0（4 筆）**：藍田路 `way/297138329@node/258784609`、
  `way/297138329@node/260130551~b`、`way/254325308@node/1401138375~b`，
  藍昌路 `way/792750238@node/343047197`。
  雙向道 `centerM=0` 沒有偏心空間，`makeBay` 直接回 null。→ 面板把該區塊中央帶寬調成 >0。
- **實體島但沒開路口開口模式（2 筆）**：加昌路 `way/297133986@node/2206349230~b`
  （區塊 `@b/2206349230`）、`way/23976945@node/289126281`（區塊 `@b/256245267`）。
  `centerKind=island` 且 `islandBayMode=false` 會被 `scopeFn` 排除。
  → 面板把中央帶改成「實體島＋路口開口」。同一條路相鄰區塊設定不一致就會一段有、一段沒有。

## 已修掉的部分

- **捏合接縫**：車道面板舊版用 `stopLineEdges` 的第一條同向邊決定 `nodeLast/nodeFirst`，
  捏合過的區塊在路網圖上被舊接點切成多條邊，第一條的終點常是接縫（區塊內部節點），
  設定就寫進黑洞。已改成優先取終點落在區塊端點的那條（`src/edit/useEditor.ts`）。
  受影響區塊清單：`npm run audit:bay -- --seam-scan`（當時 32 個）。
- **短開口**：巷口間距十幾公尺的區塊放不下 `MIN_DEFORM` 儲車段。人工開啟（`present:1`）
  時改用短開口參數（漸變固定 5m、下限 11m），自動生成門檻不變。
  現況：`npm run audit:bay -- --short-list`。
