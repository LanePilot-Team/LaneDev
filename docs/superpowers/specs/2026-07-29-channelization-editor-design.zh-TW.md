# 槽化帶編輯器與一致斜紋繪製設計

## 目標

把槽化帶提升為可檢視、可保存、但必須依附偏心道的道路標線資料。系統保留自動辨別並產生合理預設；編輯者則可調整、覆寫或停用該偏心道所屬的槽化區。沒有有效偏心道的道路不可建立槽化帶。無論槽化區長寬如何，均採同一份繪製規格。

## 現況

`buildChannelization()` 目前依合併後道路的 `centerKind`、`centerM` 與自動產生的 `turn_bay` 紀錄推導黃線與槽化斜紋。編輯器能設定中央帶與偏心道，也已有單邊使用的「封口／完全忽略」選項，但尚不能獨立建立或編輯槽化區。斜紋現由多條程式路徑產生，間距假設並不完全一致。

## 範圍

- 保留自動偏心道與槽化帶辨別。
- 新增可保存、且必須隸屬於有效 `turn_bay` 的 `channelization` enhancement 紀錄。
- 所有黃色槽化區統一使用一份公尺制繪製樣式。
- 把最初圖片紅線代表的「未使用側封閉」做成通用、依道路計算的幾何。
- 保留既有 `road`、`turn_bay` journal 紀錄及其行為。

不包含：自由手繪多邊形、沒有偏心道的獨立槽化帶、改變導航規則、或改變實體分隔島的交通語意。

## 資料模型

新增 `target.type = 'channelization'`。每筆紀錄錨定在道路區塊及其所屬偏心道，而不是螢幕座標：

```ts
{
  target: { type: 'channelization', key: 'way/W@node/N[~b]#channel' },
  fields: {
    present: 1,
    mode: 'auto' | 'override' | 'disabled',
    owner_turn_bay: 'way/W@node/N[~b]',
    s_start_m: number,
    s_end_m: number,
    width_start_m: number,
    width_end_m: number,
    side: 'forward' | 'backward' | 'center',
    closure: 'none' | 'unused-side',
    style: 'taiwan-yellow-hatch-v1'
  }
}
```

`s_start_m`、`s_end_m` 是沿所選道路區塊的公尺里程；寬度在兩端之間線性變化。因此直線、彎道、不同縮放與不同投影下都能得到穩定的漸寬／漸窄槽化面。

自動候選只在所屬 `turn_bay` 有效時才會產生，並會先正規化成相同形狀。人工 `override` 取代該自動候選；`disabled` 停用它但保留歷程。若要新增槽化帶，必須先以既有偏心道控制項新增或開啟其母偏心道。

## 繪製樣式：`taiwan-yellow-hatch-v1`

- 黃色邊界與封口線沿用既有道路標線色系。
- 斜紋線寬、中心間距與傾角只在同一個渲染器以全域常數定義。
- 斜紋位置以沿道路的公尺里程取樣，絕不依幾何取樣點數或當地帶寬推算。
- 每條斜紋都裁切於計算後的槽化多邊形內，並與兩側邊界保留內縮距離。
- 合法但短或窄的區域置中畫一條自適應斜紋；窄於最小可視寬度時只畫邊界／封口線。
- 所有槽化斜紋由同一渲染器負責；偏心道只提供幾何與所屬關係，避免重複或混合密度。

## 通用未使用側封閉（最初圖片的紅線樣式）

單側偏心道使用 `closure: 'unused-side'` 時，且其斷面實際存在未使用中央空間，未使用側才建立為漸變槽化區：

1. 從有效偏心道漸變段起點開始。
2. 沿固定與移動中的黃色邊界，構成未使用側多邊形。
3. 於路口淨空線或有效偏心道入口中較上游者結束。
4. 在仍有寬度的端點補上橫向封口線。
5. 以 `taiwan-yellow-hatch-v1` 繪製該多邊形。

此作法不依範例圖片的長寬：道路可短、長、窄、寬、彎或直，均採相同建構方式與樣式。

## 編輯器行為

在既有「偏心道」編輯面板內新增「槽化帶」區段；所選進入方向沒有有效偏心道時不可使用。

- 選取偏心道後，顯示其自動候選與既有覆寫。
- 編輯者可接受自動候選、停用它，或為同一偏心道建立覆寫。
- 覆寫時，以貼齊母道路區塊的起迄把手與兩端寬度控制器調整。
- 可設定封閉類型；`unused-side` 顯示等同紅線補足的封閉幾何，`none` 則刻意不畫槽化面。
- 儲存、匯出、靜態道路資料庫持久化與 journal 折疊，均將 `channelization` 視為其他 enhancement 類型處理。

## 驗收案例與視覺證據

每個案例均保存未改動基準圖與改動後圖，中心點與縮放完全一致；另保留一次人工新增或覆寫狀態，證明不是只依靠自動判定。

| 案例 | 位置 | 必須驗證 |
|---|---|---|
| A | 援中路往高雄大學路左轉（`22.7232222, 120.2859722`） | 單側偏心道且實景有未使用側封閉；目前地圖缺少。改動後必須畫出封口與固定密度的斜紋。 |
| B1 | 後昌路／西濱公路（`22.7116111, 120.2950000`） | 有偏心道候選但沒有可封閉的未使用側；不可只因有偏心道就新增槽化線。 |
| B2 | 後昌路 747（`22.7098302, 120.2967033`） | 單側偏心道；審核未使用側是否被明確封閉，作為單側封閉規則驗證。 |
| C | 後昌路 761（`22.7101883, 120.2963853`） | 雙側偏心道且已有槽化線；保留近似且一致的畫法，不要求與實景逐筆完全相同。 |

## 測試

- 單元測試：紀錄正規化、漸變多邊形、以公尺取樣的間距、斜紋裁切、短窄回退、覆寫優先序與停用自動候選。
- 既有偏心道測試：不得重複產生斜紋，導航／偏心道語意不得改變。
- 在隔離功能分支執行建置與目標測試。
- 視覺審閱：A、B、C 三處的改動前／改動後／人工編輯圖。
