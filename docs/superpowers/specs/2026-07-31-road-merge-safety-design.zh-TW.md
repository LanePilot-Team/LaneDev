# 道路捏合安全性與舊資料復原設計

**日期：** 2026-07-31
**狀態：** 等待使用者審閱
**分支：** `codex/road-merge-safety-design`

## 問題

LaneDev 目前的道路捏合過度接近破壞性的幾何合併：它可能移除或替換原本連接其他道路的道路身分與路口節點，將第一段道路的屬性直接套用到結果，並讓導航從不完整的路網自行推測轉向是否合法。

這會形成四個彼此相關的問題：

1. 捏合前有連接的側路可能變成導航無法進出的孤兒道路。
2. 捏合可能排除原本合法的路徑搜尋狀態，使很短的行程被替換成大幅繞路。
3. 主路有實體中央分隔島且只有單側入口時，繪圖仍可能把 OSM 分段點畫成完整路口。
4. 導航可能允許車輛在連續中央分隔島處左轉、穿越或迴轉。

這項操作的本意不是「刪除兩條道路，再用一條新道路取代」，而是：

> 在保留來源道路拓撲、來源追溯與標註資料的前提下，宣告跨越 OSM 分段接縫的視覺與導航連續性。

在本次範圍內的分隔道路情境中，捏合也明確宣告中央分隔島在該處持續存在。側路只連接相鄰車道方向；若現地有允許左轉的中央島開口，就不屬於這種捏合。

## 已確認的領域規則

- 現地中央島若有允許左轉的開口，不得使用「連續中央島」模式捏合該入口。
- 主路中央島、車道標線與一般道路樣式須跨越接縫連續繪製。
- 接縫不得替主路增加停止線、轉向箭頭、槽化帶、路口缺口或其他路口樣式。
- 側路本身若有明確標註，仍可保留側路端點的停止線或箭頭。
- 主路兩個合法行駛方向的直行都必須可導航。
- 側路只能與物理上相鄰的車道方向互通，且仍須遵守來源道路的單行限制。
- 導航不得跨越中央島左轉、直穿或把接縫當成迴轉點。
- 即使繪圖不呈現完整路口，OSM 路口身分與標註來源仍須保留。

## 目標

- 除非有明確的轉向限制，否則保留捏合前的每一條道路連接。
- 避免道路捏合使無關道路不可達，或排除原本合法的短路徑。
- 在單側入口處連續繪製實體中央島與主路樣式。
- 在相同接縫落實禁止跨越中央島的導航規則。
- 保留來源節點、來源路段、每段屬性與標註身分。
- 遇到不安全或語意不明的捏合時拒絕套用，不再默默沿用第一段道路欄位。
- 讓日誌式捏合可追溯、可預覽並可撤銷。
- 盡量救回既有捏合成果，不要求整批重新人工標註。
- 以稽核與測試偵測連通性喪失、違法轉向、異常繞路及繪圖接縫回歸。

## 非目標

- 只靠幾何自動判斷現地中央島是否真的有開口。
- 修改或校正與本功能無關的車道標註內容。
- 全面替換既有道路前處理、雙向道路配對、繪圖或導航架構。
- 自動捏合方向性衝突，或車道／中央島樣式不相容的道路。
- 刪除歷史日誌紀錄。
- 在缺少來源追溯或版本庫證據時，聲稱能自動重建所有早期破壞性修改。

## 原本 A → 修改後 B

| 項目 | 原本 A | 修改後 B |
| --- | --- | --- |
| 捏合語意 | 合併道路幾何並沿用第一段屬性 | 在保留來源道路上附加連續性限制 |
| 側路連接 | 可能隨被移除的路口節點一起消失 | 路口節點與相鄰邊仍保留於導航圖 |
| 轉向合法性 | 從合併後殘留的節點圖推測 | 在捏合接縫套用明確的轉向政策 |
| A* 搜尋狀態 | 只用目前節點作為 key | 使用目前節點與進入的有向邊作為 key |
| 中央島繪圖 | 接縫可能被畫成完整路口 | 主路中央島與樣式跨接縫連續 |
| 主路標線 | 可能新增停止線、箭頭或路口樣式 | 不因接縫新增主路停止線、箭頭、槽化帶或開口 |
| 欄位衝突 | 第一段道路無條件勝出 | 各來源路段保有欄位；接縫關鍵欄位不相容就拒絕捏合 |
| 失敗保存 | 部分有效的捏合可能仍被記錄 | 驗證具原子性；失敗不產生活躍限制 |
| 撤銷 | 介面可能顯示可復原，但日誌沒有真正停用紀錄 | 撤銷追加 tombstone，並從來源道路決定性重建 |
| 舊紀錄判定 | 找不到目前 key 就可能被視為孤兒 | 依序重播並查詢目前 key、來源追溯、節點快照與歷史版本 |

## 架構

本次修改分成五個責任清楚的單元。

### 1. 捏合限制模型

新版捏合紀錄描述的是來源道路上的疊加限制，而不是取代來源道路的新道路：

```ts
interface RoadMergeConstraintV2 {
  schemaVersion: 2
  mode: 'visual_continuity' | 'continuous_median_side_access'
  primarySegmentKey: string
  secondarySegmentKey: string
  junctionNodeId: number
  sourceSegmentKeys: string[]
  sourceNodeIds: number[]
  supersedesMergeKey?: string
}
```

`visual_continuity` 用於沒有特殊側路限制的單純 OSM 分段接縫。`continuous_median_side_access` 用於本次確認的分隔道路情境，並啟用禁止跨越中央島的轉向政策。

序號、時間、作者、操作與目標身分仍由既有日誌提供。V2 只保存可重播此語意所需的穩定欄位與來源追溯。

來源 `RoadFeature` 不會被取代。它們的身分、節點、幾何、方向性、車道屬性與 `sourceSegments` 仍是權威資料。

### 2. 依序捏合解析器

解析器按照日誌順序處理活躍紀錄。每個來源引用依下列順序解析：

1. 活躍道路完全相符的 segment/block key；
2. 活躍道路的 `sourceSegments` 來源追溯；
3. 紀錄保存的來源節點快照與幾何；
4. 離線遷移工具查詢 Git 保存的歷史道路資料庫。

正式執行環境只使用前兩項與已遷移完成的穩定 V2 紀錄。Git 歷史查詢只屬於離線復原工具，不成為正式環境相依性。

解析結果必須在每筆日誌實際套用時逐筆記錄。不得只查看全部重播完成後的道路快照來推測成敗，因為較早的合法來源可能被後續捏合吸收。

### 3. 轉向政策

導航圖保留每一條來源邊與路口節點。捏合接縫提供允許轉向函式：

```ts
isTransitionAllowed(incomingEdge, junctionNode, outgoingEdge): boolean
```

對 `continuous_median_side_access` 而言：

- 主路兩個合法方向的直行轉換都允許；
- 側路只與物理上相鄰的車道方向互通；
- 來源道路的單行限制仍具最高權威；
- 禁止跨中央島左轉、直穿與迴轉；
- 不會替捏合前沒有相鄰的道路憑空建立新連接。

相鄰車道方向與轉向類別，須由路口附近的有向邊幾何，以及兩側車道／來源身分共同判定。若幾何無法唯一辨識相鄰車道方向，驗證失敗並要求人工確認。系統不得用道路陣列順序猜測。

### 4. 繪圖接縫政策

繪圖器收到獨立於導航拓撲的接縫描述：

```ts
interface RoadMergeRenderSeam {
  junctionNodeId: number
  mainSourceSegmentKeys: string[]
  suppressMainIntersectionStyle: boolean
  keepMedianContinuous: boolean
}
```

在連續中央島接縫：

- 主路中央島與一般車道線／道路邊界樣式跨節點連續；
- 只抑制因接縫產生的主路停止線、箭頭、槽化帶、缺口及路口端帽；
- 側路幾何仍連接到相鄰車道方向；
- 保留側路自身明確標註的端點樣式；
- 即使短小視覺殘段需要隱藏，也不得刪除或隱藏導航道路。

繪圖抑制只屬於呈現中繼資料，不能把道路標成 deleted 或移除導航圖的邊。

### 5. 復原與稽核服務

離線稽核會針對每一筆活躍舊捏合輸出：

- 原始序號、時間、作者與捏合 key；
- 原始主路段與次路段 key；
- 解析後的來源身分與接縫節點；
- 建議模式；
- 欄位相容性與幾何檢查；
- 路徑與連通性比較；
- 分類與理由。

分類如下：

- `replayable`：目前身分可解析且驗證通過；
- `recoverable_via_provenance`：目前精確身分已消失，但 `sourceSegments` 或節點快照能唯一找回；
- `needs_manual_review`：有多個候選，或無法安全判斷現地語意；
- `legacy_destructive`：目前資料庫已無來源，需要從歷史版本重建；
- `invalid`：證據顯示紀錄中的路段無法形成所要求的接縫。

## 捏合驗證

V2 紀錄生效前必須完成驗證，而且整個操作具原子性。

### 必要檢查

- 兩個來源引用都能唯一解析。
- 兩段主路在宣告節點相接，且形成合理的連續走向。
- 明確指定捏合模式。
- 道路方向與單行行為能支援所要求的主路直行。
- 車道數、分隔設施、中央樣式、道路類別及其他影響導航／繪圖的接縫欄位相容。
- 連續中央島模式能明確判斷相鄰車道方向與允許的側路轉向。
- 操作不會移除相鄰邊、來源身分或標註引用。
- 預覽路網通過連通性與路徑檢查。

道路名稱與非關鍵中繼資料差異會列入報告，但絕不以「採用主路段值」處理。由於來源路段仍各自存在，無害的中繼資料可以分段保存；若差異使接縫在視覺或導航上產生歧義，則阻止啟用。

### 原子性結果

- 成功時只追加一筆活躍 V2 限制。
- 失敗時不追加任何活躍捏合限制，並回傳結構化原因。
- 預覽失敗不得留下部分修改的道路、被刪除的殘段或部分導航限制。

## 導航設計

### 搜尋狀態

A* 搜尋狀態由節點 ID 改為：

```ts
interface RouteState {
  nodeId: number
  incomingEdgeId: string | null
}
```

`gScore`、`fScore`、`closed` 與 `cameFrom` 都使用完整狀態身分。原因是兩條路徑即使抵達同一節點，也可能因進入邊不同而具有不同的合法出口。若只因該節點曾被走訪就排除第二種抵達方式，可能直接消除原本合法的短路徑。

### 路網建立

- 捏合前的每一條有向邊都保留。
- 展開下一條邊時查詢轉向限制。
- 除非某個轉向遭禁止，否則成本與啟發式計算不變。
- 只在繪圖上隱藏的殘段仍可導航。
- 路徑重建會將狀態邊對應回保留的來源道路身分。

### 路徑安全不變量

每一筆成功捏合都必須符合：

- 所有相鄰道路所在的弱連通元件與捏合前相同；
- 捏合前合法的主路直行仍合法；
- 只移除明確禁止的跨中央島轉向；
- 不新增跨中央島或原本不相鄰的轉向；
- 不受該捏合影響的路徑仍保有原本可達選項；
- 除非所有較短候選都使用新禁止的轉向，否則路徑膨脹超過設定容許值時，驗證失敗。

## 既有捏合復原

目前檢查到的日誌含有 48 個活躍且不重複的舊捏合 key。在檢查快照中：

- 42 筆可由現行流程重播；
- 6 筆找不到完全相符的 key，但來源 OSM 道路仍存在於目前資料的雙向道路配對 `sourceSegments` 中；
- 47 筆保存次路段節點快照；
- 全部仍保有序號、時間、作者與來源 key 等日誌追蹤資訊。

這些數量只代表遷移輸入，不保證每筆現地語意都正確。

### 遷移程序

1. 凍結一份原始道路資料庫與日誌快照，以便重現。
2. 依順序重播舊紀錄並產生復原報告。
3. 宣告孤兒前，先沿來源追溯解析被吸收的路段。
4. 在不修改正式日誌的情況下建立 V2 候選。
5. 執行欄位相容性、繪圖、路網連通性、禁止轉向與路徑膨脹檢查。
6. 預覽 `recoverable_via_provenance` 與 `needs_manual_review` 紀錄。
7. 候選通過確認後，追加一筆停用舊活躍目標的 tombstone，再追加含 `supersedesMergeKey` 的 V2 限制。
8. 使用原始來源道路資料庫與完整日誌進行決定性重建。
9. 所有活躍 V2 紀錄通過發布稽核後才發布。

遷移不會就地修改或刪除任何歷史紀錄。

### 無法使用的紀錄

無法使用的紀錄不會被默默保留，也不會被抹除。

- 若來源能唯一重建，遷移會產生可審查的 V2 候選。
- 若實體中央島語意不明，只要求組員確認局部接縫與允許轉向，不必重新標註整條道路。
- 若來源曾遭破壞性移除，復原工具從 Git 歷史抽取候選，並與目前幾何及標註比較。
- 審查後確認無效的舊效果會以追加式 tombstone 停用，再從來源道路重建路網。
- 既有相依標註透過穩定來源追溯重新對應；若無法唯一對應，列入報告而不是直接丟棄。

任何接縫若同時缺少已驗證的原始拓撲與明確轉向政策，都不得由遷移程序發布。

## 撤銷與追蹤介面

捏合檢視器顯示：

- 目前狀態與模式；
- 作者、時間、序號及原始捏合 key；
- 來源道路、接縫節點與被吸收的來源追溯；
- 允許與禁止轉向預覽；
- 繪圖預覽；
- 受影響標註與路徑稽核結果。

「撤銷捏合」會針對活躍限制追加 delete/tombstone，並從原始來源道路重建，不會刪除歷史。預覽必須明示：完整撤銷會同時恢復原本路口繪圖與原本轉向行為。若現地中央島仍存在，使用者應修正或以新版限制取代，而不是直接發布單純撤銷結果。

「以 V2 重新套用」會建立通過驗證、並以 `supersedesMergeKey` 連回舊紀錄的新限制。

## 失敗處理

- 找不到完全相符的來源 key：先查詢來源追溯，再回報孤兒。
- 找到多個來源候選：不得自動選擇，分類為人工確認。
- 接縫欄位不相容：拒絕套用，並列出衝突欄位與值。
- 無法判斷相鄰車道方向：拒絕啟用連續中央島模式。
- 路徑安全不變量失敗：拒絕套用，並提供受影響起終點與前後路徑比較。
- 繪圖不變量失敗：拒絕套用，並指出多出或缺少的接縫樣式。
- 日誌寫入失敗：維持舊的活躍狀態不變。
- 日誌追加後重建失敗：禁止發布，並回報從哪個序號開始重播分歧。
- 無法取得歷史重建資料：保留舊追蹤並標為 `legacy_destructive`；在查完版本庫歷史前不得宣稱不可復原。

## 測試

### 解析與驗證測試

- 解析完全相符的活躍路段 key。
- 解析被雙向道路配對吸收到 `sourceSegments` 的路段。
- 依序重播連鎖捏合，不將較早來源誤判為孤兒。
- 拒絕多個來源追溯候選。
- 拒絕相反或不相容的單行方向。
- 遇到關鍵車道／分隔設施／樣式衝突時拒絕捏合，不沿用第一段值。
- 拒絕相鄰車道方向不明的幾何。
- 捏合失敗後，來源道路與活躍日誌狀態完全不變。

### 導航測試

- 捏合後，原本連接的側路仍可到達。
- 主路兩個合法方向都能直行導航。
- 側路與相鄰車道方向之間的右進／右出可用。
- 連續中央島處的左轉、穿越與迴轉不可用。
- 以不同進入邊抵達同一節點時，A* 保留不同搜尋狀態。
- 合法短路徑不會被替換成大幅繞路。
- 只在繪圖隱藏的殘段仍存在於導航圖。
- 無關路線的可達性與成本不變。

### 繪圖測試

- 中央島與主路樣式跨接縫連續。
- 主路不新增停止線、箭頭、槽化帶、中央島開口或路口端帽。
- 側路明確標註的端點樣式仍可見。
- 有中央島開口且不應捏合的測試資料維持一般路口繪圖。
- 視覺抑制絕不把道路標成導航 deleted。

### 復原測試

- 使用凍結的目前日誌測試資料產生決定性的報告。
- 正確分類精確解析、來源復原、語意不明、歷史破壞與無效案例。
- 保留原作者、時間、序號與 key 供追蹤。
- tombstone 加 V2 取代紀錄能決定性重播。
