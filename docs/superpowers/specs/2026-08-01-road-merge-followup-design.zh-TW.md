# 道路捏合後續修正與舊資料升級規格

**日期：** 2026-08-01  
**狀態：** 已由使用者確認  
**實作分支：** `codex/road-merge-safety-implementation`

## 目標與範圍

本次工作分成三個可獨立審查、回退的 commit：

1. 捏合／撤銷後保留地圖位置與編輯上下文，並補齊繪圖回歸測試。
2. 只使用最新 `origin/anna` 正式道路資料升級舊版捏合；目前工作樹內的測試操作不得進入正式資料。
3. 修正導航起終點無法精確區分同一道路兩個行駛方向的問題。

## Commit 1：功能修正

### 現況

捏合或撤銷後必須整頁重載，才能避免同時保留新舊 MapLibre 大型圖層而使頁面耗盡記憶體；但重載會遺失相機位置、模式與正在編輯的道路。

### 修改後

- 儲存前把相機中心、縮放、方位、俯仰、目前模式與道路識別資訊寫入一次性 session state。
- 正式道路資料與 journal 載入完成後才恢復狀態，隨即清除一次性資料。
- 若原道路因捏合而改變 block key，以 OSM id、來源 block key 與接合節點依序尋找等價道路；找不到時仍恢復相機與模式，不造成崩潰。
- 保留整頁重載，不重新採用會造成記憶體崩潰的圖層原地重建。
- 測試必須證明新版捏合撤銷後恢復兩段道路，舊版升級後也能撤銷並恢復兩段繪圖，而且中央島不再保持捏合狀態。

## Commit 2：舊資料版本升級

### 唯一正式來源

- 遠端：`origin`
- 分支：`anna`
- 基準 commit：`7d2121d2391e7f4149e2572d3bf7965c00fb0cfe`
- 不得沿用本工作樹 `public/data/road_database.json` 中 seq 2903 之後的測試捏合／撤銷。

### 稽核結果

最新 `anna` 資料共有 48 筆有效舊版捏合：

- 已升級：43 筆，其中 40 筆可直接追溯、3 筆可由來源鏈追溯。
- 已回退：5 筆，其中 4 筆來源候選不唯一、1 筆兩段端點相距 21.7 公尺。
- 永久遺失來源：0 筆。

### 遷移規則

- 已升級：追加 tombstone 停用舊紀錄，再追加 schema v2 紀錄；v2 必須包含接合節點、主次道路原始快照、來源 key 與原 seq。
- 已回退：只追加 tombstone 停用舊捏合，使系統使用 `anna` 基礎 segments 重新呈現未捏合道路。
- 不刪除或改寫歷史 journal，不直接修改基礎 segments 幾何。
- 遷移須為冪等；重跑不得再次追加相同升級或回退。
- 正式報告分成 `upgraded` 與 `rolled_back` 兩區，每筆包含道路名稱、merge key、原 seq、處理結果與人工複查原因。
- 報告另記錄來源 commit、資料 SHA-256、各類數量及升級後資料 SHA-256。

## Commit 3：導航方向修正

### 現況

點選道路時雖能判斷靠近哪個方向，但建立路徑時又把點投影到共用中心線，並同時連接兩個方向；因此同一道路兩側的起終點可能得到相同或反向路線。

### 修改後

- snap 結果保留選中的有向 edge，而不是只保留中心線座標。
- 起終點暫時節點只連接該方向合法的前後端點；單行道及既有限制仍須生效。
- 側路進入已捏合主路時，只能右轉進中央島同側方向；不得把捏合節點當成可跨越中央島的左轉路口。
- 搜尋狀態繼續保留 incoming edge，避免合流後遺失方向與轉向限制。
- 測試覆蓋同一道路相反方向點選、單行道、側路右轉進同側主路、側路禁止跨中央島，以及短路徑不應被迫繞遠路。

## 驗收條件

- 三個 commit 的檔案範圍互不混雜，commit message 以中文為主。
- Commit 1 後，捏合／撤銷仍安全重載，但回到原視角與編輯道路。
- Commit 2 後，報告恰有 43 筆「已升級」與 5 筆「已回退」；撤銷任一已升級項目可恢復原始兩段道路。
- Commit 2 的正式資料可由 `origin/anna@7d2121d` 加上遷移工具重現，且不含本工作樹測試紀錄。
- Commit 3 後，同一道路兩側點選會產生符合該側方向的路徑。
- 所有道路捏合測試、導航測試、TypeScript build 與資料稽核通過。
