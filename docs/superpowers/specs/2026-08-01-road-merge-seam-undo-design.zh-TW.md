# 道路捏合接縫撤銷設計規格

**日期：** 2026-08-01

**狀態：** 設計已由使用者同意，等待書面規格確認

**實作分支：** `codex/road-merge-safety-implementation`

## 目標

撤銷道路捏合時，只解除使用者選擇的接縫，不連帶取消後續仍有意保留的捏合。若來源區塊依序為 `A → B → C`，先執行 `A + B → A`，再執行 `AB + C → A`，撤銷 `A-B` 接縫後應得到 `A｜BC`。仍相連的 `B-C` 群組改以 B 為承載路段，不產生新的 OSM Way ID。

## 已評估方案

1. **依來源鏈重建連通群組（採用）。** 還原有序來源區塊、移除指定接縫，再為仍相連的多區塊群組產生替代捏合紀錄。此方案保留使用者意圖，並使用穩定來源識別，不以幾何距離猜測。
2. **連鎖刪除所有相依捏合。** 雖然安全，但過度取消；撤銷 `A-B` 時也會刪除使用者仍想保留的 `B-C`。
3. **依距離尋找鄰近替代道路。** 不採用；道路很長、正反向並排或存在分岔路口時，最近道路不一定是正確來源。

## 資料模型與演算法

- 每筆 schema v2 捏合視為兩個相鄰來源群組之間的一條「接縫」。
- 使用 `primary_source`、`secondary_source`、`junction_node` 與既有重播結果內的來源關係，還原有序的原子道路區塊。
- 撤銷指定接縫時：
  1. 找出該筆有效捏合，以及後續所有主群組包含它的相依捏合。
  2. 建立這些紀錄共同代表、順序唯一的原子區塊鏈。
  3. 只移除使用者指定的相鄰邊。
  4. 將道路鏈切成多個連通群組。
  5. 為指定紀錄及所有將被替代的相依紀錄追加 tombstone。
  6. 每個仍包含兩個以上原子區塊的群組，依相鄰順序追加 schema v2 替代紀錄；群組第一個原子區塊成為承載者。
- 範例：目前有 `A+B` 與 `AB+C`；移除 `A-B` 後，停用兩筆舊紀錄並追加 `B+C`，結果為 `A｜BC`。
- 替代紀錄保留存活群組原本的有效合成繪圖屬性，同時保留各原子來源快照，供未來繼續撤銷。
- 不改寫 OSM ID，也不修改 canonical 靜態 segments 幾何；只追加 journal 紀錄並改變記憶體內的重播結果。

## 安全條件與歧義處理

只有符合以下條件才允許自動重定位：

- 每個原子區塊都有穩定 block key 與來源快照；
- 每條保留接縫只連接唯一一對相鄰區塊；
- 道路鏈順序唯一；
- 用候選 journal 預演時，所有替代捏合都能成功解析。

若歷程形成分岔、舊資料缺少來源、存在多種區塊順序，或預演無法重播，則不追加任何 journal 紀錄。畫面維持現狀，並提示無法自動解除此接縫，需人工確認。

## 操作與儲存流程

- 按鈕仍顯示「撤銷捏合」，語意改為「解除這個捏合接縫」。
- 儲存前以完整交易內容預演目前道路捏合視圖。
- 成功訊息說明停用了幾筆舊紀錄、重定位了幾筆保留捏合。
- 所有 tombstone 與替代紀錄一次追加完成後，只執行一次資料庫 flush 與一次安全頁面重載。
- 寫入失敗不得重載；保留目前畫面並顯示儲存錯誤。
- 重載後沿用既有相機位置與編輯道路還原功能。

## 測試

- 已有 `A+B`、`AB+C`；撤銷 `A-B` 後保留 `B+C`，A 獨立。
- 撤銷 `B-C` 後保留 `A+B`，C 獨立。
- 四區塊鏈解除中間接縫時，兩側未受影響的群組皆保留。
- 替代捏合以存活群組第一個區塊為承載者，且不建立新的 OSM Way ID。
- 相依舊紀錄均有 tombstone，之後新增捏合時不可意外復活。
- 分岔或來源快照缺失時不追加任何紀錄。
- 完整交易必須先通過預演，才能儲存與重載。
- 既有獨立捏合撤銷、導航及繪圖測試必須維持通過。

## 驗收條件

- 撤銷 `1080697514 + 1080697102` 時，停用其相依的 `1080697514 + 1080697358`，並替換為 `1080697102 + 1080697358`。
- 最終繪圖結果為 `A｜BC`；導航與繪圖只把仍保留的 `B-C` 接縫視為捏合。
- 不產生新的 OSM Way ID，實作 commit 不得修改 `public/data/road_database.json` 的基礎 segments。
- 不支援的舊版或分岔歷程必須安全失敗並顯示原因。
- 道路捏合焦點測試、相關完整測試及 TypeScript build 全數通過。
