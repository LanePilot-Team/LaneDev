# 十字型側路中央帶捏合與道路儲存提示設計

## 目的

支援 OSM 看起來是十字路口、但現地中央帶實際連續的情況。中央帶兩側的側路只能進出各自相鄰的主路方向，不得跨越中央帶、跨帶左轉或直接穿越到另一條側路。同時，道路編輯按下儲存後必須提供可信的處理進度提示。

## 範圍

- 主路捏合接縫存在兩條以上側路時，只要每條側路皆可獨立判定，就允許安全捏合。
- 主路原本合法的兩個方向仍可直行。
- 保留既有 T 字路口行為及舊 journal 相容性。
- 任一側路無法判定時，拒絕整筆捏合。
- 道路編輯加入「開始儲存、儲存成功、儲存失敗」三階段提示。
- 本功能不修改或遷移正式道路資料。

## 逐側路進出限制模型

既有 `oneSideEntryAccess` 項目增加選填的 `sideRoadKey`：

```ts
interface OneSideEntryAccess {
  nodeId: number
  allowedBack: boolean
  sideRoadKey?: string
}
```

`sideRoadKey` 使用切割後道路識別 `way/{osmId}@b/{blockNode}`。沒有 `sideRoadKey` 的項目仍代表舊版「整個接點共用」規則；有 `sideRoadKey` 時，規則只在導航進出該條側路時生效。

只有一條側路時，執行期可保留舊版無 key 表示法，維持既有序列化資料及測試相容。存在多條、且各自鄰接不同主路方向的側路時，必須使用逐側路規則。

## 捏合判定

在使用者選取的主路接縫：

1. 找出包含接縫節點、且不是兩個選定主路區塊的所有道路。
2. 每條側路都必須以該節點為端點；若道路從節點中間穿過，視為無法判定。
3. 個別計算每條側路鄰接主路 forward 或 backward 方向。
4. 每條側路都必須恰好得到一個合法鄰接方向。
5. 全部判定成功時：
   - 接受捏合；
   - 在兩個導航主路區塊分別登記每條側路的進出規則；
   - 接縫仍登記為連續中央帶屏障。
6. 任一側路判定失敗時，拒絕整筆捏合且不寫入 journal。

拒絕訊息會優先顯示側路名稱，同時包含 block key，並說明原因：接縫不是側路端點、幾何點不足，或無法唯一判定鄰接方向。

## 導航行為

- 主路駛入相鄰側路：允許。
- 側路駛入其相鄰主路方向：允許。
- 主路跨中央帶駛入對側側路：禁止。
- 側路駛入主路對向：禁止。
- 兩條側路經接縫互相直穿：由中央帶屏障禁止。
- 在捏合接縫迴轉：禁止。
- 主路沿相同實體方向直行：允許。

導航轉向判定會先用「對方道路的切割後 key」尋找逐側路規則；找不到時才退回舊版無 key 規則，以維持既有 T 字路口相容。

## 重播與撤銷

逐側路規則會在道路捏合重播時依目前道路幾何衍生，不新增正式人工標註欄位。road merge journal 仍採只追加形式，沿用既有主段與次段快照。撤銷捏合時必須清除該筆捏合產生的全部逐側路規則，並恢復原本已存在的進出規則與中央帶屏障狀態。

繪圖承載道路吸收其他道路屬性時，進出規則必須以 `nodeId + sideRoadKey` 作為識別，避免中央帶兩側的規則互相覆蓋。

## 道路編輯儲存提示

使用者按下「儲存並套用」後：

1. 依目前行為將設定套用到記憶體道路並重繪。
2. 立即顯示「道路設定已套用，正在儲存…」。
3. 主動等待靜態編輯資料落盤，而不只等待原本的 debounce 計時器。
4. 實際寫入成功後顯示「道路設定已儲存並套用」。
5. 寫入失敗時顯示「設定仍保留在此瀏覽器，但尚未寫入資料庫」，並附實際錯誤內容。

送出後編輯面板仍維持目前的關閉行為。若偏心道或機車停等格因空間不足無法繪製，最終提示仍必須保留這項警告，不得被儲存成功訊息靜默蓋掉。

## 測試條件

- OSM 共用十字節點、現地中央帶連續且有兩條對側側路時可以成功捏合。
- 每條側路只能右進、右出其相鄰主路方向。
- 任一側路都不能切入主路對向或穿越到另一條側路。
- 主路直行保持可達，接縫迴轉仍禁止。
- 任一側路無法判定時拒絕整筆捏合，並指出道路識別與原因。
- 既有單側 T 字路口與舊版無 key 規則測試維持通過。
- 多筆逐側路規則經過複製、繪圖承載道路吸收、重播及撤銷清理後仍完整。
- 儲存提示只在對應的開始、成功與失敗階段顯示正確狀態。
