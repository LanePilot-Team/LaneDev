# 車道感知導航與 HUD 同步設計

## 狀態

本設計已於 2026-08-04 完成設計審查並獲得核准。本文件定義後續實作行為，但不授權遷移或發布正式道路資料。

## 目的

讓路線規劃遵守各進場車道允許的行駛方向，並讓導航線、車道 HUD 與換道建議共用同一份車道計畫。若某車道明確只允許不相容的方向，導航不得從該車道完成轉向；若可靠車道資料缺失，導航仍可維持可用，但 HUD 必須揭露此建議為系統推測。

## 範圍

- 初次路線規劃與每次重新規劃都套用車道方向合法性。
- 選出一條主要建議車道，並保留其他相容車道作為次要選擇。
- 導航線畫在選定車道上，且導航線換道與 HUD 提示同步。
- 將換道困難度加入路線成本，但一般的準備距離不足不直接視為絕對禁行。
- 保留汽車、機車、兩段式左轉、轉向槽化道、右轉道與 GPS 導航既有行為。
- 新增系統推測與換道距離較短的明確提示。

## 非目標

- 不使用一般消費型 GPS 推測或確認車輛實際所在車道。
- 駕駛仍在原導航道路上時，不因未走主要建議車道而重新規劃。
- 不建立完整車道連接圖；目前資料不具備完整的路口車道連接關係。
- 本功能不編輯、遷移或發布正式道路標註資料。
- 未取得額外核准前，不合併或推送功能分支。

## 共用車道決策模型

新增職責單一的車道決策解析器，供路由、導航線幾何與 HUD 共同使用。解析器輸入進場有向道路、maneuver、車種及可選的下一個 maneuver，輸出下列車道決策：

- 主要建議車道索引；
- 相容的次要車道索引；
- 明確不相容的車道索引；
- 決策屬於可靠資料或系統推測；
- 開始車道提示的準備距離；
- 換道數與困難度成本；
- 是否需要顯示換道距離較短的警告；
- 導航線幾何所使用的目標橫向偏移。

解析器使用既有已整合的標註／OSM 車道指引。資料優先序維持不變：符合路口的人工標註、路段方向標註、OSM；缺失值可以推測，但推測不得覆蓋明確行駛方向。

決策結果保存於 route／maneuver。`laneBand()` 與 HUD 都讀取保存後的決策，不再各自解讀車道方向，因此 HUD 主要高亮與導航線所在車道具有一致且可重現的結果。

## 整合路線搜尋

`RoadGraph` 嘗試從進場 edge 轉入下一個 edge 時，就必須評估車道合法性。

1. 將道路轉換分類為實際 maneuver 動作。
2. 依動作與車種解析相容車道。
3. 若所有車道資料皆可靠，且沒有任何車道允許該動作，拒絕此轉換。
4. 若至少一條車道允許該動作，保留此轉換並選出主要車道。
5. 若部分或全部相關車道方向未知，使用推測候選保留此轉換，並將決策標記為 `inferred`。
6. 將換道困難度加入路線成本，優先選擇其他條件合理且較容易準備的路線。
7. 只有明確方向不相容、實體阻隔、既有進出限制或其他既有硬性路由規則，才絕對禁止轉換。

若道路層級的最短路線包含禁止轉向，搜尋必須繼續尋找合法替代路線。若不存在合法替代路線，規劃結果應說明沒有符合車道方向限制的路線。

## 相容行駛方向規則

- `right` 與 `slight-right` 需要可右轉車道。
- `left` 與 `slight-left` 需要可左轉車道。
- `through` 需要可直行車道。
- `through;right` 等複合車道同時相容於列出的兩種動作。
- 明確只標示 `through` 的車道不可用於右轉。
- 未知方向不等於明確禁止。
- 迴轉優先使用明確的 `reverse` 或 `uturn` 車道。若沒有迴轉標記但存在可左轉車道，可將最內側左轉道作為系統推測的迴轉建議；若所有車道都明確只允許直行／右轉，則禁止迴轉路徑。

## 主要與次要車道選擇

主要車道依下列順序選擇：

1. 排除明確不相容的車道。
2. 純轉向道優先於複合轉向道。
3. 同類候選中，優先選擇從目前規劃車道換道數最少者。
4. 仍同分時，右轉選最外側，左轉選最內側。
5. 使用下一個 maneuver 前瞻，避免相近路口造成先向外移、隨即又急切向內的不必要線形。

其他相容車道保留為次要合法選擇。只有缺少可靠相容車道時，才可考慮未知車道；明確不相容的車道永遠不可成為推測 fallback。

## 機車規則

- 兩段式左轉第一階段檢查直行動作，而不是直接左轉動作。
- 選擇最外側且允許直行的車道。
- 純右轉道不得用來進入兩段式待轉區。
- 若沒有任何車道允許第一階段直行，該兩段式左轉路線不可用。
- 因台灣機慢車通常靠右行駛，機車轉彎後一般回到最外側合法車道。
- 若下一個 maneuver 距離很近且必須立即準備其他動作，前瞻結果優先於轉彎後靠外側的預設規則。
- 既有機車專用道、機車左轉道與待轉區標註仍具有最高權威。

## 轉彎後的車道位置

- 汽車右轉後先進入新道路最外側合法車道。
- 汽車左轉後先進入新道路最內側合法車道。
- 機車轉彎後先進入最外側合法車道；下一 maneuver 很近時，由前瞻決定連續車道計畫。
- 若回到一般中央巡航車道會額外產生不必要或不安全的換道，導航線不得在轉彎後立刻掃回中央。

## 準備距離與導航線幾何

HUD 與導航線共用同一個計算後的準備距離。

- 基準為 maneuver 前 250 公尺。
- 道路速度較高、需跨多條車道、有轉向槽化道／右轉口袋道或 maneuver 相近時，解析器可以提早準備。
- 到達同一個路線距離時，HUD 開啟主要車道高亮、顯示換道文字，導航線同時開始平滑橫向偏移。
- 導航線應在路口前完成換道，或依槽化道／口袋道的入口幾何進入。
- 既有橫移速率限制與實體漸變段視窗繼續生效，導航線不可瞬間跳動。
- 準備區間重疊時，使用 maneuver 前瞻形成單一且連續的車道計畫。

## 換道困難度

若可用距離短於理想準備區間，只要仍存在相容車道及實體入口，該轉換仍屬合法。路線應增加換道困難度成本，優先選擇其他條件合理且較容易準備的路線。

若沒有合理替代路線，保留此合法路線，並在 maneuver 完成或重新規劃取代前持續顯示黃色小字：

> 前方換道距離較短，請注意安全；若無法換道請繼續行駛，系統將重新規劃。

此提示只提供建議，不得要求駕駛立即進行不安全的急切換道。

## HUD 呈現

車道 HUD 有三種視覺狀態：

- **主要建議：** 最明顯高亮，且必須與導航線所在車道完全一致。
- **次要相容：** 較弱高亮，表示該車道合法但不是系統首選。
- **不相容：** 非高亮／灰色呈現。

只要選定動作有使用缺失車道方向資料，就顯示 `車道建議（系統推測）`。可靠人工標註／OSM 指引不顯示推測提示。部分缺失資料可以推測未知車道，但已知不相容車道仍維持非高亮。

HUD 可顯示例如 `請向右變換 1 個車道，進入右轉道`。這只是路線建議，不代表系統已偵測駕駛完成換道。

## GPS 與重新規劃

- 車輛圖示維持真實 GPS 位置，不強迫吸附到建議車道線形。
- 不從 GPS 橫向位置偵測、確認或懲罰車道層級的遵循情況。
- 駕駛仍在原導航道路但位於不同車道時，不重新規劃。
- 確認道路層級偏離後，從最新 GPS 位置重新規劃，並對新路線套用相同車道合法性解析器。
- 保留連續定位點的抖動保護與重新規劃冷卻，避免單一錯誤定位反覆重畫路線。

## 錯誤處理

- 禁止轉向存在合法替代路線時，自動改選替代路線，不顯示錯誤。
- 完全沒有合法路線時，顯示 `找不到符合車道方向限制的路線`。
- 車道資料缺失不是規劃錯誤，透過系統推測提示揭露。
- 換道準備距離較短不是規劃錯誤，透過黃色小字與路線成本偏好揭露。
- 中央分隔、單側進出、車種通行限制與道路捏合屏障等既有硬性限制，永遠優先於推測資料。

## 測試

### 車道決策單元測試

- 所有車道只允許直行時，拒絕右轉轉換。
- 純右轉道優先於 `through;right` 車道。
- 沒有純轉向道時，複合轉向道仍屬合法。
- 多條純轉向道依最少換道數與內／外側 tie-breaker 選擇。
- 部分未知資料可以推測未知車道，但不可使用明確不相容車道。
- 迴轉優先 `reverse/uturn`，使用左轉道 fallback 時必須標記推測。
- 機車兩段式左轉選最外側可直行車道，並拒絕純右轉道。

### 路由測試

- 最短轉換沒有相容車道時，`RoadGraph` 找到合法替代路線。
- 沒有任何合法替代路線時，回傳車道方向專用錯誤狀態。
- 換道困難度影響路線成本，但不覆蓋硬性合法性。
- 相近 maneuver 產生連續的前瞻車道計畫。
- 重新規劃與初次規劃使用相同車道限制。

### 幾何與 HUD 測試

- 導航線目標車道等於 HUD 主要建議車道。
- 次要相容車道可與主要車道及不相容車道清楚區分。
- HUD 啟動與導航線開始換道使用相同準備距離。
- 轉向槽化道／右轉口袋道幾何控制實際進入視窗。
- 機車轉彎後位於最外側；只有前瞻需要時才例外。
- 系統推測與換道距離較短提示只在對應條件成立時出現。

### 迴歸與視覺驗證

- 執行車道決策、`RoadGraph`、lane-band、lane-preview 與 HUD 的聚焦測試。
- 執行 `npm.cmd run test:all`。
- 執行 `npm.cmd run build` 與 `git diff --check`。
- 使用真實瀏覽器確認導航線保持在主要高亮車道內、不同縮放下換道線形平滑，以及 HUD 主要／次要狀態保持可讀。

## 驗收條件

只有在下列條件全數成立時，功能才算完成：所有明確不相容轉向都不會出現在初次規劃或重新規劃路徑；資料缺失時導航仍可用且揭露為系統推測；導航線與 HUD 永遠共用相同主要車道與準備距離；機車與兩段式例外遵守上述規則；相近 maneuver 維持連續線形；所有聚焦測試、迴歸測試、production build 與瀏覽器檢查皆通過。
